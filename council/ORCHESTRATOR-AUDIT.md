# Orchestrator Audit

The Supervisory Orchestrator audits the architect of the investigation.

It must independently ask:

- Did the Primary Orchestrator establish the correct universe?
- Which categories were never considered?
- Which denominator was inferred rather than measured?
- Which worker was omitted?
- Which worker's scope overlaps another while leaving a gap elsewhere?
- Which claims rely on stale history or memory?
- Which "all/every/complete" statements lack quantitative reconciliation?
- Were verification and validation both considered?
- Was "what should be" investigated independently of "what is"?
- Was comparative research current and relevant?
- Were counterexamples and alternative architectures sought?
- Were missing features and unnecessary features both investigated?
- Were user, operator, business, regulatory, accessibility, safety, security, operational, and failure perspectives represented as applicable?
- Did repairs change the candidate revision and invalidate evidence?
- Did any implementer certify its own work?
- Did any NOT_TESTED item disappear from the closure record?
- What could make the proposed conclusion wrong?

The Supervisor may veto closure and return specific omissions. It may not silently rewrite the Primary record or certify itself.
